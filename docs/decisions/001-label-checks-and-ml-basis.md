# 001. Проверка этикетки с абсолютным допуском и база «на 100 мл»

## Контекст

FR-05 требует, чтобы `|ккал − (4·Б + 9·Ж + 4·У)| / ккал ≤ 0.15`. При 0 ккал (вода, энергетики без сахара) формула делит на ноль, а при 1–5 ккал округление на этикетке легко даёт больше 15%. Напитки и энергетики составляют заметную часть рациона.

Напитки маркируются на 100 мл, а модель данных и контракты считают КБЖУ на 100 г (FR-04, D-04).

## Решение

1. Проверка формулы: `|ккал − (4·Б + 9·Ж + 4·У)| ≤ max(0.15 · ккал, 5)`. Абсолютный допуск 5 ккал закрывает нулевые и малокалорийные продукты, относительный 15% работает как раньше для остальных.
2. У позиции появляется база `basis`: `g` или `ml`. КБЖУ хранятся на 100 единиц базы (`per_100`), размер упаковки `pack_size` и количество в строке записи `amount` — в тех же единицах.
3. Проверки диапазонов (`Б + Ж + У ≤ 100`, `ккал ≤ 900`, все значения ≥ 0) одинаковы для обеих баз.
4. Код не пересчитывает граммы в миллилитры. Если пользователь указал граммы для позиции в мл (или наоборот), считаем плотность равной 1.

Переименования: `per_100g` → `per_100` + `basis`, `pack_weight_g` → `pack_size`, `entry_items.grams` → `amount`, `grams_source` → `amount_source`, `grams_estimate` → `amount_estimate`.

## Альтернативы

- **Только относительный допуск, при 0 ккал проверку пропускать.** Отклонено: пропускается ошибка вида «0 ккал, 10 г углеводов».
- **Хранить всё на 100 г, напитки пересчитывать через плотность.** Отклонено: плотность напитков неизвестна, а пересчёт вносит ошибку в цифры этикетки, которые должны совпадать точно.
